# Smart Router 1.0.0 Release Notes

## Release summary

Smart Router 1.0.0 is a self-hosted, provider-agnostic AI resource orchestrator. It combines generic provider onboarding, request/usage ledger, quota-aware scheduling, Control Plane administration and production deployment documentation.

## M0–M1 — Hardened routing core

- Stable request IDs and structured routing behavior.
- `RouterEngine`, `ResourceCandidate`, `ProviderDriver` and legacy compiler boundaries.
- Provider-specific catalog compatibility remains outside scheduler abstractions.

## M2 — Generic provider onboarding

- Provider templates for OpenAI-compatible and Anthropic-compatible APIs.
- Generic Gemini and CLIProxy bridge drivers.
- Add, test, discover and import models without source edits or gateway restart.
- Immutable configuration revisions with validation and activation.

## M3 — Ledger and quota engine

- Request, attempt and usage provenance.
- Token and output reservation accounting.
- Safety buffer, idempotency, reconciliation and failover reservation transfer.
- Quota resource graph supports request, token, credit and concurrency dimensions.

## M4–M5 — Scheduling and failover

- Capability/state/budget/concurrency filters.
- Deterministic scoring and policy presets: `auto-free`, `fast`, `coding`, `review`, `critical`.
- Paid fallback policy and budget gates; route simulation exposes effective policy and project budget eligibility.
- Runtime health distinguishes short-lived `RATE_LIMIT` from long-term `QUOTA_EXHAUSTED`.
- Streaming failover only before first output, covered by acceptance regression tests.
- Dry-run route simulation without upstream calls.

## M6 — Complete Control Plane

Available API surfaces under `/api/admin/v1`:

- Overview, version and Settings/Security.
- Providers, credentials, connection test and model discovery.
- Model import into routes and Routes/Policies editor.
- Usage ledger requests/details/stats.
- Revision list/detail/activation/rollback.
- Audit history and alert lifecycle.
- Project/API-key management.
- Legacy YAML migration.

All admin routes require bearer authentication. Credential values and project keys are never returned after creation.

## M7 — 1.0 hardening

- Fernet encryption at rest.
- Full Docker Compose stack with gateway, worker, web, PostgreSQL and Redis.
- Backup/restore procedures.
- Operations runbook and SLO targets.
- Acceptance smoke tests and runtime version endpoint.

## Deployment

```bash
cp .env.example .env
# Set SMART_ROUTER_KEY, SMART_ROUTER_ENCRYPTION_KEY and POSTGRES_PASSWORD.
docker compose up -d --build
docker compose ps
curl http://localhost:8320/version
```

Use `docs/ops/runbook.md` for migration, health, ledger, audit and troubleshooting procedures. Use `docs/ops/backup-restore.md` for PostgreSQL and Redis backups.
